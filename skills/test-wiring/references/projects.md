# 工程、网络与出图

## 工程结构

- 工程 JSON 使用 `version: 1` 声明文件格式。工具版本可用 `--version` 查询。通过 `sheets` 声明图页的 `id` 和 `title`，通过 `instances[].sheet` 给实例指定图页。同页按可用空间自动排版和换行，空间不足时调整图页分配。
- 工程 JSON 与它引用的照片同工程保存。工具可从指定路径读取工程。`instances[].template` 填 `型号` 或 `型号@版本`，以 `part` 查询结果为准。省略版本时使用当前器件库内的最高数字版本。固定版本时查阅该版本的器件说明。
- `id` 是供网表使用的稳定键，`reference` 是图上显示的位号，两者在工程内各自唯一。`name` 可覆盖模板默认名称，`note` 可覆盖默认小字。模板支持时，`station: "02"` 将以小字显示并保留前导零。`parameters` 采用 `part` 给出的字段定义。
- `view` 填 `symbol` 或 `photo`，以模板支持的视图为准。为实例只选一种主视图。照片作为同页独立说明时，用 `sheets[].photo` 填 `file`、`caption`、`marks`。`file` 相对于工程 JSON，`marks[].endpoint` 为 `实例ID.端子ID`，`marks[].at` 为照片内 0–1 的相对坐标。

## 配置线路颜色

`colors` 是工程顶层的对象，同一配色应用于工程的各页和两种导出格式。颜色按 `#RRGGBB` 填写，大小写均可。

| 字段 | 作用 | 省略后的颜色 |
|---|---|---|
| `colors.internal` | 模块内部导线、触点、端点、引脚线、端子文字和照片接点标记 | 蓝色 `#1C5C94` |
| `colors.external` | 外部引线及对应网名 | 蓝色 `#1C5C94` |

两项独立生效。省略整个 `colors` 时，两类线路都用默认蓝色。下面的配置将外部接线画为深橙色，内部使用默认蓝色。

```json
{
  "colors": {"external": "#9A4A16"}
}
```

查看成图时，核对 USB 等整口连接器与其余模块端子同色，以及外部引线与其网名同色。模板中的颜色用途标记见[制作模块模板](templates.md#制作-svg-符号)。

## 从参考图录入网络

1. 先核对所有模板和参数下有效的端子。逐条追踪参考图上的引线、交点以及同名标签，用 `实例ID.端子ID` 记录端点。确认发送和接收的两端、正负极、地线区分以及原图留空的端子。
2. 每个网络在 `nets` 中用唯一的 `name` 和完整的 `members` 数组定义。保持已有网名，包括中文、空格和加减号。同名网跨页复用同一个网络定义，出图时每个相接端子显示同一网名。
3. 普通网络至少有两个工程内端点，每个端点只加入一个网络。若参考图给出了外部网名，但工程只覆盖其中一个已知端点，可使用 `external: true`。空接脚保留在模板中，工程里不为其创建网络。
4. 从图纸修改已有工程时，保留已经核对的端点与网名。改变通道数后，重新查询该实例的端子，并根据已确认的接线调整受影响的网络。

下列例子中的 `adapter` 是实例 ID，`TXD` 是该实例所用模板的端子 ID。

```json
{
  "name": "继电器1-RXD",
  "members": ["adapter.TXD"],
  "external": true
}
```

## 检查生成结果

```sh
python wiring.py validate 工程.json
python wiring.py render 工程.json 接线图.svg
python wiring.py render 工程.json 接线图.pdf
```

- `validate` 返回图页数以及每个网络的端点清单，端点以 `位号.端子ID` 显示。与参考图逐项核对端子和网名。导出以用户要的格式为准，SVG 多页工程用 `-p01.svg`、`-p02.svg` 等逐页输出。
- 打开生成图，检查端口方向、引线起点、网名与引线末端的垂直对齐及空接情况。实物视图核对引线是否指向照片上的接口中心。模块名称和下方小字应相对图形居中，多模块同页时检查标题、模块与网名留有足够空间。
- 若画面排版不足，改配件分组或项目分页，必要时修改模板的端子布置，再重新生成。把资料未能确认的连接或端子单独列给用户核对。
